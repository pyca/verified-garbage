# Working: P-521's fused doubling on x86-64 (clean room)

Working notes, appended to before the code each entry decides. The listed
files were removed unopened. Disclosed to the coordinator: the header (20
lines) of `Impl/Mont/X86_64/Cms.lean` and `Impl/Mont/X86_64.lean` lines
860-1060 (`mulPX`, `sqrPX`, `xCanon`) were read. From them, and from general
recollection of a library, these are *barred* here: the decomposition
`w = 12 X Y² − 9 (X² − Z⁴)²`, `X₃ = 4 X Y² − w`, `3 M w − 8 Y⁴` and any
`C a − D b` fused operation; a forced carry-in of one to canonicalize.

## Entry 1: the correct starting point (before any code)

What must exist: ECDH's window loop for `p521x`, and a doubling for P-384's
window and joint loops. The tree already has, for every curve, proven:
`doubleIn` (in-place `dblJMul`, 4M + 4S + 12 cheap) and `exchangeJ4`.
So step 0 uses exactly those, no new field code:
* P-384 (`exchangeP384Adx`, `jointDoubleAdx`): `doubleIn` on the ADX modulus.
* P-521 (`exchangeP521Adx`): `exchangeJ4` on `p521x`.
Then measure step 0 and the base as black boxes, and decide from the profile
what to write.

## Entry 2: what a lazy field would save (before any code)

`p = 2^521 - 1`; nine words hold 576 bits, so 55 bits spare: a sum of up to
2^55 field elements fits with no reduction. A product's input may be any
number whose words the product accepts, as long as the product's own bounds
hold. Counts for `dblJMul`: 8 products, 12 cheap operations, each cheap
operation a 9-word carry chain plus a full reduction (about 9 instructions
loads + 9 + 9 stores + reduction ~12). A sum without reduction is 27
instructions, a difference `a - b + 2^k p` is a subtraction with a constant
folded in. At 2.5-3 cycles per word-op chain the 12 cheap operations are of
the order of 12 x 20 = 240 cycles against 8 x ~130 = 1040, so lazy reduction
could save at most a tenth of a doubling. To be measured, not assumed.

## Entry 3: measured, and the candidate (before any new code)

Step 0 (generic code only) against the base as a black box, Xeon 2.3 GHz,
8 fresh copies: ecdh_p521 181.97 -> 201.42 us (10.7% slower), ecdh_p384
118.10 -> 126.87 (7.4%), ecdsa_p384_verify/64 122.81 -> 131.96 (7.4%).

Cost model, from what the tree states in prose: a product of nine words is a
call that saves six registers in xmm, copies an operand (9 words) and
dispatches square/product (~50 instructions round ~350); a linear operation
is ~45 instructions with its own full reduction, and reads and writes memory.

Own formula, from dbl-2001-b with one change of variable, u = 2Y:
    u = 2Y;  g = u^2 (= 4Y^2);  S = X g (= 4XY^2);  d = Z^2
    M = 3 (X - d)(X + d);  X3 = M^2 - 2S;  Z3 = u Z
    Y3 = M (S - X3) - g^2 / 2       (8Y^4 = g^2 / 2)
Four squares, four products, and these linear operations, with the bound
each result has when operands are <= p and no reduction is done:
    u = Y + Y            <= 2p      add, unreduced
    X + d                <= 2p      add, unreduced
    X + (p - d)          <= 2p      see below
    3 (product)          <= 3p      r + r + r: two carry chains at once
    M^2 + 2 (p - S)      <= 3p      r + c + c, c = p - S: two chains at once
    S + (p - X3)         <= 2p
    g^2 / 2              <= p       a rotation right by one of 521 bits
    M(..) + (p - h)      <= 2p
What a product takes: a Montgomery product of a, b below 2^576 is right when
a b < R p = 2^1097, so ANY of the sums above can be operands, in pairs
(2p 2p = 2^1044). Only what is subtracted needs to be <= p (or fit the slack
below), and what is handed to code that wants a canonical value.

p - b for b <= p: p is all ones, so p - b is b's complement in 521 bits: NOT
each word and add 512 to the top word (`~b8 + 512 = 511 - b8 mod 2^64`); NOT
leaves the flags alone, so a + (p - b) is one carry chain. That replaces both
the load of p and the "borrow then add p back".

Reduction of V < 4p to <= p (no comparison): h = V >> 521 (<= 3), V' = low +
h, one carry chain; V' <= p + 3, so if V' >= 2^521 its low words are < 3 and
a second h' = V' >> 521 is added to word 0 alone, no chain. Result <= p and
congruent. p itself (congruent to 0) can appear; a product's output is
canonical already, so only X and Y of the point can be p, never Z. p maps to
0 by an AND over all nine words when the canonical value is needed (end of
the four doublings).

Rejected: reducing every linear result (what step 0 does); any a C - b D
fused operation and w = 3S - M^2 (barred above); Karatsuba for the product
(not my task, the product functions stay as they are).

## Entry 4: prototype numbers and two changes (before the Lean code)

Prototypes: own generated assembly calling the existing product function as a
black box (200 doublings in a chain, TSC 2.3 GHz, best of 300):
step 0's two doublings 1309 (615-655 each); entry 3's doubling 546; with a
leaner call (no xmm saves, no operand copy, no dispatch) 531. So the linear
operations are the saving (~80-100 TSC a doubling), the call only 3%.
Full canonicalization of X and Y in every doubling would cost 20 TSC, so X
and Y stay <= p ("weak") within the four doublings and are made canonical
once, at the end (p -> 0 by the AND of all words).

Change: carry H = 2Y instead of Y across the four doublings. Then
    g = H^2 = 4Y^2;  S = X g;  Z3 = H Z;  X3 = M^2 - 2S
    H3 = 2 Y3 = (2M)(S - X3) - g^2          (16 Y^4 = g^2)
which needs neither the doubling of Y nor the halving of g^2 in every
doubling: only 2M, an unreduced sum. H = 2Y before the first doubling and
Y = H/2 (rotation) after the fourth.

The order of the operations: a search over the topological orders of the
dependency graph, timed on this machine (random restarts; script below in
the final entry), not chosen by hand.

## Entry 5: the order found (before the Lean code)

`proto_gen.py` (the linear operations), `proto_search.py 1 10` (random
topological orders, 40 candidates x 10 rounds, mutation of the best eight):
best 500.4 TSC a doubling, in the order
    d tm tp g m0 m S mm x3 g2 w m2 z3 q h3
(d = Z^2, tm = X + (p-d), tp = X + d, g = H^2, m0 = tm tp, m = 3 m0,
S = X g, mm = m^2, x3 = mm + 2(p-S) folded, g2 = g^2, w = S + (p-x3),
m2 = m + m, z3 = H Z, q = m2 w, h3 = q + (p-g2) folded); unsearched orders
520-585. The top three are within 1 TSC: the first is taken.
